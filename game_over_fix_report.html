Game Over & Reset Logic Fix Report

The Main Issue: NodeList vs. Element

The variable choices is a NodeList (a list of elements), not a single button. Setting choices.disabled = true does nothing because the list itself doesn't have a disabled property—only the individual buttons inside it do.

This meant players could keep clicking buttons even after the game ended.

1. Disabling Buttons at Game Over

🔴 Before (Buggy)

Tried to disable the list, which failed silently.

if (wins == 5) {
  choices.disabled = true; // Does nothing!
}

🟢 After (Fixed)

We iterate through every button in the list and disable them one by one.

if (wins == 5) {
  choices.forEach(c => c.disabled = true);
}

2. Re-enabling Buttons on Reset

🔴 Before

The resetGame() function only removed the outlines but forgot to un-freeze the buttons.

choices.forEach((choice) => {
    choice.style.outline = "none";
    // Buttons remained disabled
})

🟢 After

We explicitly set disabled = false so the game can be played again.

choices.forEach((choice) => {
    choice.style.outline = "none";
    choice.disabled = false; // Back to normal
})

3. Visual Feedback (Reset Icon)

🔴 Before

The center icon logic was missing or incomplete, meaning the user didn't see the "Reset" arrow clearly.

🟢 After

We explicitly swap the image source to the reset icon on Game Over, and back to the normal arrow on Reset.

// On Game Over
nextImg.src = IMAGES.reset;

// On Reset
nextImg.src = "img/next-icon.png";

The game now correctly "freezes" at 5 points and "unfreezes" when you click the reset button.

Reset & Sizing Fix Report

The Issues

  1. Circles shrinking: The <img> tags were missing the class="placeholder". This meant they lost their width: 100% styling and defaulted to their intrinsic size or a size affected by padding.
  2. Padding glitch: Setting style.padding = "0px" inline could conflict with external CSS or browser defaults differently than removing the style entirely.
  3. Reset button broken: The reset function was being called immediately when adding the event listener, rather than waiting for the click.

1. HTML Fix: Adding Missing Classes

🔴 Before (Missing Class)

The images had no class, so they didn't respect the responsive sizing rules we added to CSS.

<div class="result" data-index="1">
  <img src="img/odin-rps-placeholder.png" />
</div>

🟢 After (Added Class)

Added class="placeholder" to all result images.

<div class="result" data-index="1">
  <img class="placeholder" src="img/odin-rps-placeholder.png" />
</div>

2. JS Fix: Cleaning Inline Styles

🔴 Before

Explicitly setting 0px might leave an inline style that overrides CSS rules.

img.style.padding = "0px";

🟢 After

Setting to empty string removes the inline style completely, letting CSS take over.

img.style.padding = "";

3. JS Fix: Event Listener

🔴 Before

Calling the function with () runs it immediately instead of passing it as a reference.

next.addEventListener('click', resetGame());

🟢 After

Passing the function name waits for the click.

next.addEventListener('click', resetGame);

These changes ensure the game resets cleanly and visual elements maintain their correct size.
